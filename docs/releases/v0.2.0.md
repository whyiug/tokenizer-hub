# Tokenizer Hub v0.2.0

Release snapshot: `2026-08-09`

## Highlights

- Expanded the catalog from 71 to 88 entries with current OpenAI, DeepSeek, GLM, Kimi, MiniMax, Gemma, Llama, and Mistral representatives.
- Added independent Raw, Chat, and Tools support flags. The snapshot has 86 exact Raw entries; Qwen3 8B additionally has fixture-backed exact Chat and Tools support.
- Added pinned source evidence and SHA-256 verification for 29 shared Hugging Face tokenizer assets. The seven new stored asset groups add about 25 MiB.
- Moved authoritative Chat/Tools serialization to the backend and removed the universal frontend ChatML-like formatter.
- Added lifecycle metadata and made GPT-5.6 Sol the default. Historical OpenAI and Llama 2 entries remain searchable as legacy records.
- Kept the two unreleased DeepSeek V4 preview identifiers visible but disabled instead of mapping them to the V3.2 tokenizer.

## Added models

- OpenAI: GPT-5.6 Sol, Terra, Luna.
- DeepSeek: DeepSeek V4 Flash 0731.
- Z.ai: GLM-5.2.
- Moonshot AI: Kimi K3 and Kimi K2.7 Code.
- MiniMax: MiniMax M3.
- Google: Gemma 4 E2B, E4B, 12B, 26B-A4B, and 31B instruction variants.
- Meta: Llama 4 Scout and Maverick Instruct.
- Mistral AI: Mistral Small 4 119B 2603 and Mistral Medium 3.5 128B.

## Breaking API change

`POST /v1/tokenize` and `/v1/tokenize/batch` now require structured, mode-specific payloads. Raw accepts `text`; Chat accepts ordered `messages`; Tools accepts `messages` plus `tools`. Responses now include the authoritative `serializedText` and `mode`. Clients that previously sent a preformatted chat string must migrate to the structured form.

## Deliberately deferred

Laguna 2.1, Tencent HY3, Cohere Command A+/North Mini Code, and representative Ministral 3 sizes remain candidates for v0.2.1. Claude, Gemini, API-only Qwen/Meta/Kimi models, Grok remote tokenization, OpenRouter usage counts, multimodal token visualization, provider API keys, automated catalog sync, pricing, and quality rankings remain out of scope.

Remote token-ID APIs are not used: they would transmit user input to a third party and require credentials, privacy disclosure, rate limiting, and abuse controls. A future remote mode would need an explicit product boundary rather than masquerading as local support.
